# Provider HTTP contracts

Implementation: `src/api/provider-routes.ts`, migration `002_providers.sql` (frozen). Plugin: `registerProviderRoutes(app,database,settings,runtime?)`. Worker: `runProviderWork(database,settings,runtime?)`. Optional runtime is trusted server configuration/test injection, never browser input. Default `EXTERNAL_SERVICES_ENABLED=false` disables external calls with HTTP503; local transcript upload/review remains available. No live external evidence has been obtained. Tests use isolated real PostgreSQL and local HTTP provider stubs only.

All tenant routes below have prefix `/v1/churches/:churchId/providers`; frontend proxy uses `/api/v1/...`. Authenticate using the existing session cookie. Mutations need `X-CSRF-Token`, `Idempotency-Key` (8–200 chars), and matching Origin when supplied. Adoption additionally requires `If-Match` of the current editor aggregate. Existing capability grants apply; successful OAuth never creates membership. Routes return ordinary JSON with error status/code/message through the application's error handler. No endpoint returns credentials, encrypted secrets, full telephone numbers or raw audio jobs.

`AIProposal` is `{workflow,baseRevisionId,fields:[{path,date:null|string,suggestion,evidence:[{sourceId,spanId}],scriptureReferences:string[],warnings:string[]}],status:'proposal_awaiting_review',provenance:{provider,responseId,model,promptVersion,profileVersion,inputHash,outputHash,sources:[{revisionId,sha256}],usage:{inputTokens,outputTokens}}}`. Workflows: `week_outline`, `day_plan`, `field_assistance`, `study_draft`, `revision_help`. Assistance selects one field. Week proposals include six plan fields per requested date and remain bound to the requesting aggregate/base; adoption of a date must match that aggregate's calendar. Separate per-day generation is appropriate for independently edited slots.

AI source selection is checked at enqueue, execution and adoption. Plans may use reviewed sources linked to their series; content may use only sources included in the exact approved plan's canonical source snapshot. A newly uploaded source must enter a renewed plan revision and approval before it can ground content. Selecting a reviewed source from another series returns422 `source_dependency_mismatch`. Adoption additionally compares the source span digest with recorded proposal provenance. These constraints align proposals with the canonical v2 revision source binding introduced by migration006.

Plan paths: title, primaryScripture, learningObjective, outline, discussionQuestion, notes. Study paths: title, body, reflection, discussionQuestion, application, smsPreview. A study_draft proposal requires all six fields, including a nonempty complete devotional body. The worker loads the exact currently approved plan payload from the database and supplies it as untrusted context alongside the approved plan revision ID; callers cannot substitute browser plan text. Adoption maps `primaryScripture` to `.reference`, outline lines to array, `smsPreview` to `outboundPreview` and body directly to content.body. It preserves untouched editor fields and never marks Scripture/theology verified. Selective body adoption alone does not bypass required title/reflection/discussion/application checks or separate human content approval. Whole-study publication still requires the complete manual/domain review process.

## Callbacks and worker behavior

`POST /v1/provider-callbacks/pco/:churchId/:connectionId`: application/json raw bytes, X-PCO-Webhooks-Authenticity hex HMAC-SHA256. Select encrypted subscription secret from confirmed tenant connection, verify exact bytes before parsing, check discovered event catalog and organization, persist deduplicated inbox and reconcile job before200. Never infer deletion from a missing page/404.

`POST /v1/provider-callbacks/twilio/:churchId/:connectionId?intentId=...`: application/x-www-form-urlencoded, X-Twilio-Signature. Canonical external URL uses configured APP_ORIGIN plus `/api/v1/...`; configure exactly this public callback path and preserve query bytes. Validate all form parameters and account/sender/intent binding. STOP revokes consent and suppresses pending work. Duplicate events have one effect; delayed queued status cannot erase terminal delivery evidence. Conflicting terminal evidence requires reconciliation.

Worker claims jobs using durable row locks; no automatic retry after possible provider acceptance. Interrupted running jobs become submission_unknown for review. Token budgets reserve atomically and reconcile actual successful usage; failure/unknown provider usage conservatively consumes reservation. Before SMS submission recheck current approval/plan/published pin, active publisher, active recipient membership, active plan/content approvers with their respective grants, exact preview, consent version, suppression, sender, quiet hours and expiry. Membership authority rows are share-locked during the final transactional claim. Unknown zone holds; known zone defers until09–20 local within approved expiry. Committing submitting before network allows recovery without blind duplicate sends; STOP or authority revocation can race with a request already in flight and cannot recall it. Submission_unknown keeps this uncertainty visible. SMS status is provider evidence, not member-read proof. PCO refreshed tokens commit before importing, so an import rollback cannot discard a rotated refresh token.

Server configuration: `EXTERNAL_SERVICES_ENABLED`, `PCO_TOKEN_ENCRYPTION_KEY` (canonical base64 32 bytes), `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_TRANSCRIPTION_MODEL`, `PCO_CLIENT_ID`, `PCO_CLIENT_SECRET`, `PCO_REDIRECT_URI` (supports `{churchId}` placeholder), `PCO_WEBHOOK_SECRET`, `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM` or `TWILIO_MESSAGING_SERVICE_SID`, `TWILIO_CHURCH_ID`, `TWILIO_SENDER_SCOPE`, `TWILIO_ACTIVATION_APPROVED`, `SOURCE_ALLOWED_HOSTS`. No browser secret entry. Audio processing additionally requires an operator-supplied `inspectAudio` implementation; test fixtures explicitly inject their own inspector and are not evidence of malware scanning or audio duration accuracy.

Human/license/provider evaluation, real account OAuth/callback/SMS roundtrips, provider retention/registration and production operational evidence remain blocked. Local tests do not close those gates.
