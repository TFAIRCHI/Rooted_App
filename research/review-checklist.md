# High-risk design review checklist

Recommendations derived from [verified source entries S20-S28](evidence/security.md). Unchecked items require design evidence and relevant tests; this checklist is not an implementation or compliance claim. The main review should cross-check the architecture, schema, AI, approval, scheduling, security, and operations documents against these points.

- [ ] **Runtime isolation:** Runtime roles own no tenant tables, cannot assume privileged roles, and cannot alter policies or truncate data. Enable and force RLS; verify read and write policies and permissive-policy composition using actual runtime roles. [S20](evidence/security.md#s20)
- [ ] **Tenant integrity:** Use tenant-inclusive relationships and appropriate tenant-scoped uniqueness; test cross-tenant reads, writes, tenant reassignment, constraint disclosures, and concurrent membership revocation. Review every view and definer function for privilege escape; detailed view/function semantics need their own evidence. [S20](evidence/security.md#s20)
- [ ] **Connection context:** Authenticate membership before assigning tenant context; missing context fails closed. Set context inside each transaction from trusted code. Test pooled reuse after commit, rollback, savepoints, and exceptions, including a stale session baseline. A caller-settable tenant value cannot independently authenticate the tenant. [S27](evidence/security.md#s27)
- [ ] **Other data paths:** Trace tenant scope through uploads, object URLs, search/vector retrieval, caches, exports, background jobs, and audit access. Test hostile tenant IDs and leaked object references. RLS evidence alone cannot establish these boundaries. [S20](evidence/security.md#s20)
- [ ] **AI authority:** Keep authorization, scoped tools, and consequential-action approval outside the model. Inject hostile instructions through retrieved documents, metadata, tool results, and generated HTML; observe actual disclosures and side effects, and include benign controls and repeated attempts. [S22](evidence/security.md#s22)
- [ ] **Approval and revisions:** Bind approval to an immutable revision and publication parameters. Pin assets/templates or retain the rendered artifact. Edits invalidate affected approvals; workers never resolve a revision as mutable "latest." Test edit/approve/publish races, direct mutation attempts, and rollback as a new publication. This is a proposed application contract, not an Object Lock feature. [S22](evidence/security.md#s22), [S28](evidence/security.md#s28)
- [ ] **Retention boundary:** Distinguish runtime append-only database permissions, integrity hashes, and storage retention. If Object Lock is chosen, pin version IDs and test the configured retention mode; document privileged bypass, account deletion, and retention requirements. [S28](evidence/security.md#s28)
- [ ] **Civil-time intent:** Persist local intent, named zone, resolution policy, schedule generation, and resolved instant. Choose gap, overlap, recurrence, and downtime behavior explicitly. Test both DST transitions, non-hour transitions, timezone-data updates, and stale jobs after edits. [S24](evidence/security.md#s24), [S25](evidence/security.md#s25)
- [ ] **Atomic publication:** Commit the publication decision and outbox event together. Use stable event IDs, tenant/revision identifiers, and per-target sequence checks. Test rollback, duplicate delivery, reordering, and crashes before and after broker acknowledgment; document retry and dead-letter recovery. [S23](evidence/security.md#s23)
- [ ] **External delivery:** Distinguish queued, dispatched, provider-accepted, and delivered states. Verify provider idempotency separately; reconcile timeout-after-success. Define cancellation's dispatch cutoff and test cancel/dispatch races. Do not infer exactly-once delivery from an outbox. [S23](evidence/security.md#s23)
- [ ] **Accessible workflows:** Target WCAG 2.2 AA across authoring, approval, scheduling, authentication, and public content. Check keyboard access, focus, drag alternatives, target-size exceptions, errors, status announcements, and password-manager/paste support. [S21](evidence/security.md#s21)
- [ ] **Review evidence:** Combine automated checks with human keyboard, screen-reader, zoom/reflow, and content evaluation. Record failures, test environments, owner, and remediation; do not present prototype or scanner success as conformance. Cross-check source limitations before accepting stronger architecture claims. [S26](evidence/security.md#s26)
