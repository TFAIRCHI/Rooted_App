## Intended experience and implemented behavior

- Members use an emailed sign-in code as their only credential. No additional MFA challenge is required for reading, member participation, accepting a member invitation or signing out.
- Member sessions have no application expiry. The browser receives a Secure, HttpOnly, SameSite=Lax cookie with a 400-day lifetime, renewed on authenticated API use. Normal study visits load the member navigation and call the session API, renewing the browser cookie. Browser deletion, private browsing, device changes or browser-imposed expiry can still require sign-in. The server does not impose a 30-day or eight-hour member logout deadline. [Browser cookie lifetime limits](https://developer.chrome.com/blog/cookie-max-age-expires).
- Contributors use a separate sign-in flow with verified MFA. MFA assurance lasts up to eight hours from the signed token's authentication time. After it expires, the same session retains reading access and must verify again to use the workspace.
- Workspace, authorship, AI, approval, publication, moderation, membership administration and church creation require MFA plus current church capabilities. Signing in through the contributor application does not itself assign a church role.
- A contributor can read through a member session. Its effective church capabilities are empty until MFA is verified. Promoting a member does not upgrade an existing reading session.
- Upgrading a reading session requires the same verified account, rotates the session token/CSRF token, and revokes the prior token. Failed verification preserves the prior reading session. Sign-out removes the current server session and clears the application and OIDC-state cookies.

## Live acceptance required

- First member login requires only the email code; subsequent study links and browser restarts reuse the session. Session renewal reaches the browser through the frontend proxy.
- Sign-out immediately revokes the token; another device and cleared browser data correctly require sign-in. A member deactivated in a church cannot continue reading that church through the retained account session.
- A contributor can read without MFA, but workspace/API, owner onboarding and privileged invitations require it. Successful MFA preserves the same account and returns to the requested workspace. Failed/cancelled MFA leaves reading access intact.
- Expired contributor assurance requests MFA again without signing the reader out. Promotion during a member session does not grant workspace access; MFA never grants a church role the account does not possess.
